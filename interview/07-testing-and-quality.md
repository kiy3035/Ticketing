# 테스트 / 품질

---

### Q1. 통합 테스트 인프라를 어떻게 구성했나요?

**A.** `IntegrationTestBase` 가 **Testcontainers** 로 **MySQL 8**, **Redis 7**, **Kafka**(Confluent 7.5) 컨테이너를 띄우고, `@DynamicPropertySource` 로 Spring Boot 프로퍼티에 바인딩합니다. 로컬·CI 모두 **Docker 만 있으면** 동일하게 돌아가게 했고, 테스트 프로파일에서는 Flyway 를 끄고 JPA `create-drop` 으로 스키마를 맞춥니다. 외부 메일·SMS 는 더미 호스트/키로 막아 **네트워크 의존 없이** API·서비스 통합을 검증합니다.

> **Q1-1. E2E 전부 Testcontainers 로만 하나요?**
> **A.** 핵심 플로우는 컨테이너 기반 통합 테스트로 두고, 단위 테스트는 Mockito 등으로 빠르게 돌립니다. k6 부하는 `load-tests/` 에서 별도로 돌리는 편이 비용·시간 면에서 낫습니다.

### Q2. ArchUnit 을 왜 넣었고, 어떤 규칙인가요?

**A.** 레이어 위반은 리뷰 없이 머지되면 나중에 되돌리기 비싸서, **`ArchitectureTest`** 로 **CI 에서 깨지게** 고정했습니다. 규칙은 (1) `..controller..` 패키지가 `..repository..` 에 **직접 의존하지 않음** (2) `..domain..` 이 `org.springframework..` 에 **의존하지 않음** (3) `..service..` 가 `..controller..` 를 **참조하지 않음** 입니다. “왜 컨트롤러에서 Repository 를 안 쓰나?” 질문에 **테스트가 근거**가 됩니다.

> **Q2-1. ArchUnit 이 너무 빡빡하면?**
> **A.** 규칙은 **팀이 동의한 최소 세트**만 두는 게 좋습니다. 여기서는 포트폴리오 규모에 맞춰 세 가지만 두었고, 필요해지면 `..config..` 예외나 store 패키지 규칙을 추가할 수 있습니다.

### Q3. 동시성·락은 테스트로 어떻게 검증하나요?

**A.** **단일 JVM 통합 테스트**만으로는 레이스를 재현하기 어렵습니다. 그래서 (1) **Lua 스크립트·락 해제** 단위 테스트 (2) **부하 스크립트(k6)** 로 실제 경합·knee point 확인 (3) 코드 리뷰 시 `HoldStore`·`RedisLockService` 경로를 **정적**으로 점검하는 조합을 씁니다. 면접에서는 “동시성 버그는 테스트 한 방으로 끝나지 않는다”는 점과, **설계(원자성·이중 방어)·관측(메트릭)** 을 같이 말하면 좋습니다.

> **Q3-1. 멀티 스레드 테스트를 더 쓰고 싶다면?**
> **A.** `CountDownLatch` 로 N 개 스레드가 동시에 `createHold` 를 호출하는 **스트레스 테스트**를 붙이거나, Testcontainers Redis 위에서 **짧은 반복**으로 flaky 를 감수하고 돌릴 수 있습니다. 비용 대비 효과를 보고 선택합니다.

### Q4. 결제·웹훅 멱등은 어떻게 테스트할 수 있나요?

**A.** **HTTP `Idempotency-Key`** 는 동일 키·동일 바디 재요청 시 **동일 응답**이 나오는지 통합 테스트로 검증할 수 있습니다. Kafka 컨슈머는 **DB 플래그·상태**로 중복 소비를 흡수하므로, “이미 처리됨” 분기에 대한 **통합 테스트**가 유효합니다.

> **Q4-1. 테스트 데이터는 어떻게 정리하나요?**
> **A.** 트랜잭션 롤백, `@Sql`, 또는 테스트마다 `create-drop`/격리 DB 등 팀 표준을 따릅니다. Testcontainers 는 컨테이너 단위 격리가 되어 **테스트 간 오염**이 적습니다.

---

### Q5. CI 에서 무엇을 게이트로 두겠나요?

**A.** **단위·통합 테스트 통과**, **ArchUnit 통과**, (선택) **정적 분석/포맷**. Docker 가 없는 CI 면 Testcontainers 가 실패하므로, **CI 에 Docker-in-Docker 또는 원격 Docker** 를 맞추는 것이 전제입니다.
