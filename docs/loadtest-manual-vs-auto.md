# 부하 테스트 — 수기(Before) vs 자동 하네스(After) 비교

> 같은 `knee-point` 시나리오를 **수기**(예전, AWS k6→앱2대→RDS)와 **자동 하네스**(`loadtest-harness/`)로
> 측정해 비교한다. 목적: **자동화가 수기 결과를 재현하는지** 검증 = 자동화 신뢰성 입증.

## ⚠️ 비교 시 방법론 정렬 (중요)
- **수기**: Run1은 JVM cold라 느려서 **분석 제외**, **Run 2·3(JVM hot) 평균** 기준. 매 Run 전 Redis flush.
  (출처: [`load-test-portfolio.md`](load-test-portfolio.md) Phase 6)
- **자동**: 동일하게 맞추려면 **`--repeat 3` + 측정 직전 앱 재시작(run1 cold) + `reset_command`(매 회차 Redis flush)**.
- 아래 "자동(스모크)"은 **단일 1회(repeat 1)** 라, 사실상 수기에서 *제외하는* **cold Run1**에 해당 → **예비 참고용**.
  정식 비교는 **자동(repeat 3, hot 2·3 평균)** 칸이 채워진 뒤에 한다.

| 지표 | 수기 (Phase 6, hot 2·3·재측정) | 자동 — 스모크 1회 (예비) | **자동 — repeat 3 (hot 2·3 평균)** | 수기 대비 |
|------|------------------------------|------------------------|------------------------------|----------|
| 평균 RPS (k6) | ~2,320 ~ 2,430 /s | 1,889 /s | **2,503 /s** | ✅ 일치(약간↑) |

| max 지연 | **1m 0s** (k6 timeout) | 60.1 s | **60 s** (timeout) | ✅ 동일 |
| 실패율 | 2.6 ~ 4.9 % | 5.56 % | **3.42 %** | ✅ 범위 내 일치 |

## 1차 해석 (예비)
- **큰 그림은 일치**: max 60s timeout(동일), 에러율 ~5%대(유사 범위), RPS 자릿수(2,200+급) 비슷, knee가 고VU 구간.
- **차이의 원인 = 단일 cold run**: 스모크가 p95↑(830 vs ~480)·RPS↓(1,889 vs ~2,370)인 건, **수기에서 분석 제외하는 cold Run1**에 해당하기 때문. → 수기 방법론과 일치하는 현상(예상됨). 정식 비교는 hot 2·3 평균으로.
- **병목 진단 일치**: `hikari_pending`(DB 풀)이 병목 신호 — 수기 Phase 5의 "VU=1500 DB pending spike"와 정렬. `hold_conflict`·`lock_acquire_failures`=0 → 락/홀드 경합은 병목 아님(수기 Phase 7 정확성 결론과 충돌 없음).

## 결론 — 자동화가 수기 결과를 재현함 ✅
- **자동 repeat3(hot 2·3 평균) = RPS 2,503 · p95 462ms · 실패율 3.42% · max 60s** 가 수기 문서값
  (RPS ~2,320~2,430 · p95 ~448~537 · 실패 2.6~4.9% · max 60s)과 **문서 변동폭(±10~20%) 내로 일치.**
  → "수기로 손 측정한 결과를 자동 하네스가 동일하게 낸다" = **자동화 신뢰성 정량 확인.**
- **콜드/핫 방법론도 데이터로 검증**: run1(cold) p95 1,259ms → hot 462ms (2.7배 차이) → 수기에서 run1을
  제외한 이유가 그대로 재현됨.
- **병목 진단 일치**: hot 회차에서도 `hikari_pending` 196~242·`hikari_active` max 59(≈풀 60 포화) →
  DB 커넥션 풀 압박(수기 Phase 5 "VU1500 DB pending spike"). `lock`/`hold` 경합 0(수기 Phase 7과 일치).

## 한계 (정직)
- knee point의 **정확한 VU 구간**(수기: 1,000~1,200)은 회차 평균이 아니라 **회차 내 시계열**로 봐야 한다 →
  `charts/*.png`(회차별 시계열 겹쳐보기)로 확인. 하네스 집계표는 "안정 수치 재현"을 보여주고, VU-knee는 차트로.
- AI(Gemini) 분석은 1차 의견 — 이번 리포트에서 **서버 latency 단위(초)를 ms로 오독**한 사례 발견 →
  분석기 프롬프트에 단위 안내를 추가해 보강함(이 변경에 포함). 최종 판단은 사람.
