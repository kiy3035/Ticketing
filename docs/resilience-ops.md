## 1. 페일오버 — 부하 중 앱서버 1대 강제 종료

**목적**: 트래픽이 들어오는 도중 앱서버 1대를 강제 종료했을 때 nginx가 자동으로 살아있는 서버로 라우팅하는지, 그리고 에러율이 얼마나 빠르게 회복되는지 확인한다.

**전제 조건**
- nginx upstream에 `proxy_next_upstream error timeout http_502 http_503 http_504` 설정 ✅
- 앱서버 2대 운영 중 ✅

**시나리오**

```
k6 VU=800 부하 시작
    → 30초 안정화 확인
    → 앱서버 #1 docker stop (강제 종료)
    → Grafana 에러율 상승 → 회복 패턴 캡처
    → 앱서버 #1 docker start (복구)
    → 완전 회복 확인
```

## 2. 롤링 배포 무중단 검증

**목적**: 앱서버를 1대씩 순서대로 재배포하는 동안 k6 에러율이 0%로 유지되는지 확인한다. 서버 1대였다면 배포 중 다운타임이 발생하지만, 2대 구성에서는 nginx가 정상 서버로만 라우팅해 무중단이 가능하다.

**전제 조건**
- `server.shutdown=graceful` ✅
- `spring.lifecycle.timeout-per-shutdown-phase=30s` ✅
- nginx `proxy_next_upstream` 설정 ✅

**시나리오**

```
k6 VU=800 부하 시작
    → 30초 안정화 확인
    → 앱서버 #1 배포 (docker pull → docker stop → docker run)
    → 앱서버 #1 완전 기동 확인 (/actuator/health)
    → 앱서버 #2 배포 (동일)
    → 전체 과정 에러율 0% 확인
```
